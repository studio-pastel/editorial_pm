# エディトリアルPM（editorial_pm）

冊子の制作を、関係者（社内・クライアント・チームメンバー）で進めるためのウェブツールです。Googleスプレッドシートの台割をもとに、ページごとの進捗・コメント・図版・スケジュール・タスク・議事録・経費をまとめて扱い、デザインPDFを貼った立体の本（ページをめくれる3D）で仕上がりを確かめられます。

- 画面：GitHub Pages で配信する1枚のHTML（`index.html`）
- データ：案件ごとのGoogleスプレッドシートと、そのオーナーのGoogleドライブ
- 中継：Google Apps Script のウェブアプリ（`relay/Code.gs`）。ログインの確認と、シート・ドライブの読み書きを行います

画面側にはデータもシートのURLも入っていません。エディトリアルPMのURLに付ける `?sheet=…` で案件を選び、Googleでログインした人が、そのシートの「メンバー」タブに登録されていれば中に入れます。

## できること

| タブ | 内容 |
|---|---|
| 台割・3D | 見開きの台割と、PDFを貼った立体の本。ページを押すと詳細（進捗・コメント・図版）が開きます |
| 進捗 | 台割の「初校」「再校」など「〜校」で終わる列を工程として集計・更新 |
| スケジュール | 別のスプレッドシート（「内容」「開始日」「終了日」の見出し）をガントチャートで表示。社内は日程を変更できます |
| タスク | 担当・期限・状態で管理し、担当者別の件数も表示 |
| 議事録 | Markdownで記入（プレビュー・検索・タグ）。シートに一覧、ドライブに `.md` ファイルを保存 |
| コメント | ページへのコメントと返信。投稿すると関係するメンバーにメールで通知 |
| 図版 | ページごとの写真・図版の手配状況 |
| 経費 | 経費の登録・集計と領収書のアップロード |
| メンバー | ログインできる人と役割の管理 |

役割ごとの権限：

| | 社内 | クライアント | チームメンバー |
|---|---|---|---|
| 閲覧・コメント | ○ | ○ | ○ |
| 進捗・図版の更新 | ○ | — | ○ |
| タスクの作成・更新 | ○ | ○ | ○ |
| 議事録の作成・編集 | ○ | ○ | 閲覧のみ |
| スケジュール | 閲覧・日程変更 | 閲覧 | — |
| 経費 | 閲覧・登録 | 閲覧 | — |
| 設定・デザインPDF・メンバー | ○ | — | — |

## 自分の案件で使うには

1. **スプレッドシート**：台割のタブ（「頁」「内容」などの見出し行のある表）を用意します。「メンバー」「コメント」などのタブは、必要になったときに自動で作られます。
2. **Google Cloud**：プロジェクトを作り、「Google Auth Platform」でウェブアプリケーションのOAuthクライアントを作成します。承認済みのJavaScript生成元に、エディトリアルPMを置くサイト（例：`https://<ユーザー名>.github.io`）を登録します。使うスコープは `openid`・`email`・`profile` だけです。
3. **中継スクリプト**：[script.google.com](https://script.google.com) で新しいプロジェクトを作り、`relay/Code.gs` を貼り付けます。先頭の `CLIENT_ID` と `ALLOWED_ORIGINS` を自分の値に書き換え、関数 `authorize` を一度実行して権限を許可します。そのうえで「デプロイ」→「新しいデプロイ」→ 種類「ウェブアプリ」、次のユーザーとして実行「自分」、アクセスできるユーザー「全員」でデプロイします。
4. **画面のビルド**：`python3 src/build.py <ウェブアプリのURL> <OAuthクライアントID>` を実行すると `index.html` ができます。これを GitHub Pages などに置きます。
5. **開く**：`https://…/?sheet=<スプレッドシートのID>` を開き、スクリプトの所有者のアカウントでログインします。「メンバー」タブから関係者を追加します。

中継スクリプトが扱えるのは、スクリプトの所有者がオーナーのスプレッドシートだけです。ログインはスプレッドシートごとに有効です。スプレッドシートやドライブのフォルダの共有は「制限付き」のままで使えます。

## テスト

```sh
cd tests
sh run.sh            # Chromiumの場所を指定する場合は CHROME_PATH=/path/to/chrome sh run.sh
```

- `relay/test_relay.js`：中継スクリプトを Node 上の Apps Script の模型（`relay/gasmock.js`）で動かし、権限・入力の検証・ファイルの読み書き・安全対策を確かめます。
- `tests/e2e_*.js`：画面をヘッドレスのChromiumで開き、役割ごとの操作を確かめます。台割は架空のデータ（`tests/fixtures/daiwari.js`）を使います。

## ファイル構成

```
index.html        ビルド済みの画面（GitHub Pages で配信）
privacy.html      プライバシーポリシー
src/              画面の部品（HTML・CSS・JavaScript）と build.py
relay/            中継スクリプト（Code.gs）とテスト
tests/            画面のテストと架空のテストデータ
```

使っているライブラリ：three.js r128、PDF.js 3.11.174、marked 12.0.2、DOMPurify 3.1.7（いずれもCDNから読み込み）。
